# Internal pilot protocol (T061, not final T012)

Browser UI binds only 127.0.0.1:8080. No demo identities in default mode. Operator bootstrap creates a random password, salted PBKDF2-HMAC-SHA256 verifier (600000 iterations), and RFC6238 TOTP seed. Login requires both; accepted TOTP counter is persisted against reuse. HttpOnly/SameSite=Strict session, exact Origin/Host checks, 30-minute idle / 8-hour absolute expiry, max 100 sessions, bounded login concurrency and 10 attempts / 15 minutes. This local pilot is not OIDC/SSO/recovery completion (T013).

Each explicitly granted customer scopes device enrollment, jobs, results and audit. One local operator has an explicit `lab` grant; additional grants require local configuration. This is not the final MSP role hierarchy. Agent token is random 256-bit and stored hashed server-side; the authenticated enrollment ZIP contains its sole plaintext delivery. Revoke invalidates the token and cancels pending jobs. No real customer data or paid enrollment is implied.

Agent listener binds only 127.0.0.1:8443 and requires TLS >=1.2. Windows agent uses bundled Mbed TLS 3.6.7, validates CA, hostname and certificate lifetime. No insecure option. Local bootstrap CA has a 1-year lifetime; server certificate 3 months. CA signing private key is not retained; renewal currently requires explicit reprovisioning. This is not the T006/T016 certificate rotation design.

`POST /agent/poll` carries bounded F01 identity JSON and device Bearer token. Only the device's own non-revoked jobs can be returned. Response is `JOB <64-lowerhex-id> <64-lowerhex-nonce> F01|F04|F08\n`, Content-Length set, or HTTP 204. Job expires 5 minutes after creation. The agent accepts exactly these three zero-argument actions; it does not call a shell or accept executable paths. TLS authenticates the controller; offline job signatures are not implemented.

A job execution marker is written before collection. A bounded result is written to pending.json before upload. On restart pending result is retried; the last marked job is not executed again. A crash between marking and saving result can lose a collection; it is not retried automatically and expires. This favors avoiding duplicate execution over guaranteed delivery. Run one foreground agent per Windows session with a named mutex; one identity per endpoint/dedicated directory. Service installation and update are not yet implemented.

`POST /agent/result`: job_id, nonce, collector_id, data JSON. Server validates authenticated device/customer/collector/nonce, delivery and deadline. The same completed result may be acknowledged idempotently; conflicting replacement is rejected. Endpoint evidence remains untrusted. Payload <=256KiB; 100 total pilot jobs and 10 device records. State JSON is owner-only, atomic rename + fsync, single-server mutex; it is not a scalable database. Audit retains at most 2000 events and is not tamper-proof. No E2EE claim: local server sees plaintext results.

Collectors: F01 system identity/version/memory; F04 process snapshot (max 512); F08 IPv4 TCP table (max 512, PID mapping, no IPv6). Caps yield partial; denied/error isn't empty success. Low process priority and brief enumeration yields are implemented, not the full adaptive governor T008. x86 code is designed for XP SP3 and later; only actual execution reports establish OS coverage.

QEMU pilot route, when explicitly selected: user network `restrict=on,ipv6=off`, one explicit guestfwd from 10.0.2.100:8443 to loopback 127.0.0.1:8443 via a direct socket chardev with reconnect=1 (no subprocess; spawn=deny). No hostfwd, shared folders, SMB, or general guest egress. XP credentials must first be provisioned offline; native checks and route negative tests must be recorded. Original offline runner remains the default.

`POST /agent/check` validates TLS and device token without delivering or executing a job. `--probe agent.conf` performs this check and exits 0 only for HTTP 204. Non-secret connection errors identify the failed stage and Mbed TLS verification code.
